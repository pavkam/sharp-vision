# Terminal protocol coverage matrix

## Coverage

The state describes current repository evidence, not planned behavior. The
terminal-backend and discovery architecture refactor changes ownership and
composition only. It adds no protocol behavior and changes no support state in
this matrix. Backend extension metadata is not a support claim; the rows below
remain authoritative.

The matrix may use only: typed and implemented; decoded and observable;
extension API with safe fallback; or unsupported with a specific reason. Generic
parser framing is not misreported as semantic support. Kitty, sixel, and iTerm2
claims include Application and public-control wiring only because those paths
are covered through final output bytes and shutdown.

## Discovery and output facade

The `TerminalProtocol`/`Capabilities.Support`/`Features` discovery facade and
the `ITerminalServices` output surface, both described in the
[protocol index](index.md#discovery-and-output-facade), are reporting and
consumption layers over this matrix, not new support claims.
`Capabilities.Support(TerminalProtocol.KittyGraphics)` reports supported query
evidence only after a strict correlated APC reply. Environment names remain
tentative. Sixel output requires DA1 parameter 4 or an explicit override; iTerm2
multipart output requires an `OSC 1337 ; Capabilities` query reply or an
explicit 3.5+ contract override. `ITerminalServices` exposes no graphics member
because graphics output is a renderer-owned `IGraphicsBackend` over semantic
frame placements; it continues to expose only bell, window title, and clipboard
services.
